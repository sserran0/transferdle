# Transferdle

A daily football game: guess a player's estimated market value (source: [transfermarkt-datasets](https://github.com/dcaribou/transfermarkt-datasets)) in €M within 5 guesses.
Each guess turns green, yellow, orange or red with a ⬆/⬇ hint. Everyone gets the same player each day.

```sh
npm install
npm run dev      # dev server (adds a "replay" button and ?date=YYYY-MM-DD override)
npm test         # vitest
npm run build
```

## Player data

`src/data/players.json` is **generated and committed**. Do not edit it by hand.

```sh
npm run data                          # download the dataset and regenerate
npm run data -- --from-dir <dir>      # use local players.csv + competitions.csv
```

- **Source:** [transfermarkt-datasets](https://github.com/dcaribou/transfermarkt-datasets) (CC0). The game never contacts Transfermarkt.
- **Curation** (`scripts/curate.ts`): players active in the latest season in the Premier League, La Liga, Serie A, Bundesliga, Ligue 1, Eredivisie and Primeira Liga, valued at €1M or more, top 1,000 by value.
- **Tiers:** by value rank, as a proxy for recognisability: top 25% easy, next 40% medium, rest hard.
- **Rotation** (`dailyPlayer` in `src/lib/game.ts`): difficulty ramps through the week (Mon–Tue easy, Wed–Fri medium, Sat–Sun hard). Each tier is shuffled with a fixed seed and used in order, so no player repeats until the tier is exhausted.

## Puzzle schedule

Live puzzles come from `src/data/schedule.json`, not from the rotation directly. Each day stores a frozen copy of its player (value, club, etc.; photos are merged in by id), so **regenerating `players.json` never changes a day that's already scheduled.**

```sh
npm run schedule                 # append days up to 60 days from today
npm run schedule -- --days 90
npm run schedule:check           # validate (CI also checks it's append-only)
```

- New days use the rotation's pick, or a seeded same-tier fallback if that player appeared in the last 365 days (`src/lib/schedule.ts`).
- CI fails any PR that edits or removes an existing day. To fix a bad puzzle, change it deliberately and explain why in the PR.
- The `Schedule runway` workflow runs weekly and fails when fewer than 14 days are left, so GitHub emails you before it runs out. If it does run out, the app falls back to the rotation and logs a warning.
- Typical refresh: `npm run data && npm run images && npm run schedule`, then open a PR.

## Images

Photos are **not** taken from Transfermarkt: their terms prohibit scraping and the photos are third-party copyrighted.
Instead, `npm run images` (`scripts/build-images.ts`) finds openly licensed photos on **Wikimedia Commons**:

1. Wikidata maps each Transfermarkt player ID (property P2446) to a Commons image (P18).
2. Commons supplies the licence, author and a 400px thumbnail.
3. Only **CC0, public domain, CC BY and CC BY-SA** are kept (`isAllowedLicense` in `scripts/images.ts`). NC, ND, GFDL-only and unknown licences are dropped.

Results go to `src/data/images.json` (committed), keyed by player id and merged in `src/data/players.ts`.
The card shows the photo with a credit line linking to its Commons page, which satisfies the attribution requirement.
Players without a free photo, or whose image fails to load, show an initials avatar.
Photos are hotlinked from Wikimedia's servers, which is permitted for thumbnails; if traffic grows, self-host them.
Re-run `npm run images` after regenerating the player pool.

## Share previews

Pasting the link into iMessage, Discord, WhatsApp, X or Slack shows a card from the Open Graph and Twitter tags in `index.html`.
The tags are static on purpose: never put the day's player, value or date in them (spoilers).

- **Image:** `public/og-image.png` (1200x630) is generated by `npm run og` (`scripts/build-og.ts`). It reuses the app's pitch, palette and font, and is drawn at 240x126 then scaled exactly 5x so every edge is a hard pixel. Regenerate and commit it after changing the wordmark, colours or tagline.
- **Absolute URLs:** platforms require them, so `index.html` uses `__SITE_URL__`, filled in at build time by `vite.config.ts` from `scripts/site-url.ts`. Production and local builds use `https://transferdle.vercel.app`; Vercel *preview* builds use their own URL so a preview's image resolves. If the domain changes, edit `PRODUCTION_URL` in `scripts/site-url.ts`.
- **Testing:** platforms only fetch public URLs, so test a deployed URL (e.g. with opengraph.xyz), not localhost. They cache aggressively; if a preview looks stale, re-scrape it with the platform's debugger or add a throwaway `?v=2` to the URL you paste.

## Analytics

[Vercel Web Analytics](https://vercel.com/docs/analytics) (cookieless, no personal data) via `<Analytics />` in `src/App.tsx`.
It only reports from a Vercel deployment: turn it on once under **Project > Analytics** in the Vercel dashboard. Page views and referrers work on every plan.

Three custom events (`src/lib/analytics.ts`) measure engagement, and may need a plan that includes custom events:

| Event | When | Properties |
| --- | --- | --- |
| `game_started` | first guess of the day | none |
| `game_completed` | the game ends (once per day) | `won`, `guesses` |
| `share_clicked` | Share button pressed | none |

Properties are deliberately coarse: never send the player, the value, the date or what was typed.

## Info dialogs

Three dialogs open from the buttons in the header (`src/components/InfoDialogs.tsx`, built on the native `<dialog>` in `Modal.tsx`, so Esc, focus trapping and screen readers work without extra code):

- **? How to play** opens by itself on a first visit, then only from the button. Players who already have stats or saved guesses never get it forced on them (`src/lib/help.ts`). The colour rules shown come from the same constants the game uses (`src/lib/scoring.ts`), so they can't drift.
- **i About** covers the fan-project disclaimer (not affiliated with Transfermarkt or any club), the data source, photo credits and the privacy note.
- **Stats** shows streaks and the guess chart at any time, separate from the results panel that appears when a game ends. Stats stay in the browser (`localStorage`).

If you change what the game collects, update the privacy text in `AboutDialog`.

## Security headers

`vercel.json` sets `nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` and a **Content-Security-Policy**.
The policy is **enforced** (`Content-Security-Policy`): the browser blocks anything it doesn't allow, and logs `Refused to load ...` in the DevTools console. It was first rolled out as `Content-Security-Policy-Report-Only` to catch problems before enforcing.

- **If something stops loading in production:** check the console for `Refused to load ...` and add the missing source to the policy. To debug without breaking users, temporarily rename the key back to `Content-Security-Policy-Report-Only`.
- **Expected on Vercel previews:** Vercel's preview toolbar loads from `vercel.live` and is blocked there. It doesn't exist in production, so ignore it.
- **Keep it in sync, in the same PR as the change:**
  - a new image host goes in `img-src` (`scripts/csp.test.ts` fails if a photo host in `images.json` isn't allowed)
  - a backend on another domain goes in `connect-src` (same-domain Vercel functions are covered by `'self'`)
  - Vercel Analytics runs from our own domain, so `'self'` already covers it
- **No `data:` assets:** `build.assetsInlineLimit` is `0` in `vite.config.ts`, because Vite would otherwise inline small fonts as `data:` URIs, which `font-src 'self'` rejects.
- **No inline styles or scripts:** keep CSS in files and don't add inline `<script>` tags. Styles set from React's `style` prop are fine.

## Pixel art

The up/down arrows, the correct-answer check and the coloured attempt blocks are drawn as pixel art, not font glyphs or emoji, so they look identical on every device (iOS in particular swaps `⬆` for a coloured emoji and uses its own emoji squares).
Sprites are plain character grids in `src/lib/pixelart.ts` and render as inline SVG via `src/components/PixelArt.tsx`. To change one, edit its grid.
The attempt blocks use the same colours as the guess boxes (`--green`, `--yellow`, `--orange`, `--red`). The share text (`src/lib/share.ts`) still uses emoji squares, because pasted text can't carry drawn graphics.

## Player stats (experimental)

The card shows last full season's **club** stats, and which stats depend on position (`src/lib/statfacts.ts`):

| Position | Shown |
| --- | --- |
| Outfield (defenders, midfielders, attackers) | Games, Goals / assists |
| Goalkeeper | Games, Clean sheets |

`src/data/stats.json` is generated by `npm run stats` (`scripts/build-stats.ts`, `scripts/stats.ts`) from the CC0 `appearances` and `games` files in transfermarkt-datasets. Pass `--from-dir <dir>` to use local copies, or `--season <year>` to change the season (default 2025, i.e. 2025/26, pinned so a new season's first few matches can't replace it).

- **The dataset has no position-specific columns.** Every match row has the same fields (goals, assists, cards, minutes) for every position. The goalkeeper/outfield split is made here, and **clean sheets are derived**: the keeper played at least 60 minutes and their team conceded nothing. It is an approximation, not a Transfermarkt figure.
- **Club games only.** National-team matches (e.g. the World Cup) are excluded. All club competitions in the season are included.
- Players with no club appearances that season (about 8 of 1,000) simply show no stats.
- Like photos, stats are display-only and merged live (`src/data/players.ts`, `src/data/schedule.ts`); they never change which player or value is scheduled.
